# Mountain Dew v1 experiment

The user requested PR [commaai/openpilot#39047](https://github.com/commaai/openpilot/pull/39047)
for eGPU and Jetson, on a new `carrot-mdm` branch. The branch starts at
`carrot-wip` `deb9b425fc`. Uncommitted work in the original checkout is excluded.
The model changes belong to this experiment; `carrot-wip` stays unchanged.

- Official file: `big_driving_tinygrad.pkl`, 773,090,994 bytes, SHA-256

  SHA-256 `6a65495ec80afe8a3114c2f19dcf63a4e7d4654c2fc977e9acacb646f3f7c2c9`.

Official model bytes were obtained from the upstream `.lfsconfig` Hugging Face
endpoint and verified against the PR pointer. Vehicles use NAS HTTPS, without
adding LFS to this repository. `tools/modeld/build_mdm_package.py` verifies the
model and exact source archive before deterministically packaging the runtime.
The runtime contains unmodified tinygrad and its openpilot helpers plus license.

This model uses a persistent packed-weight arena, unlike the former protocol-5
buffer stream. Catalog serialization selects the correct upstream loader. Its
retargetable host dispatch is lowered/compiled before execution, as in the pinned
official modeld. GPU kernels and weights remain the official artifact.
The newer warp compiler is CLI-only; the adapter reconstructs its two-camera
YUV420 compilation/capture and changed-input check from the same pinned helpers.
Cached warps are prepared again for execution. The boot receipt includes the
new adapter's source hash.

Metadata extracted without executing artifact globals confirms identical input
shapes, state queues, 18,452 output values and output slices to the previous
Cinque v3 contract. The trained checkpoint differs. Keep state-output aliasing,
C3 QCOM-before-upload with its pixel validation/AMD fallback, C4 AMD warp,
internal driving model, DM, validity thresholds, timeouts and control unchanged.
Web status identifies the new artifact as Mountain Dew v1.

## Jetson remains blocked on the matching ONNX

The PR changes only the eGPU PKL. The public
[source ONNX repository](https://huggingface.co/commaai/openpilot_driving_models/tree/main)
contained `1a421175` and `f78ed37d` exports when inspected on 2026-10-07,
but no `ea1600cb` export. The current Jetlink extra catalog also lacks MDM.
The AMD compiled artifact cannot be passed to the existing TensorRT loader.

No Jetson model/spec, signed host release or SD image is changed. Jetson still
uses its existing Cinque v2; installing this branch does not make it MDM.
To finish that part, obtain the ONNX for the exact checkpoint above, verify its
hash and metadata, integrate its stateful queues with the Jetson server, publish
a separate verified host/model release, then check numerical parity and parked
latency. Another checkpoint must not be labeled MDM.

## Validation

- Verified the full official model SHA-256 before and after NAS copying.
- The branch's actual `ensure_precompiled()` downloaded and verified the full
  model and runtime over public NAS HTTPS and recognized the installed package.
- 121 focused desktop tests passed: model selection/delivery, old/new loader
  dispatch, metadata/parser, rejection, device receipts, diagnostics and existing
  QCOM/AMD warp policy. Eleven Web tests passed; generated assets rebuilt.
- [Linux CI](https://github.com/ajouatom/openpilot/actions/runs/37611443245)
  passed on integration commit `eb4c04a620`: all 121 contract tests, the actual
  pinned-runtime CPU warp capture/reload and persistent-buffer roundtrip, all
  11 Web tests and a clean generated-asset rebuild. The runtime download hash
  was independently checked in CI.
- Windows actual CPU execution could not proceed because clang is absent;
  mock/contract tests are not accelerator inference verification.

No C3/C4 eGPU inference, camera pixel comparison with this new runtime, latency,
thermal or driving validation has been performed. Existing startup smoke checks
and rejection/fallback remain required. This is an experimental eGPU integration,
not completion of the requested Jetson port or evidence of improved driving.
